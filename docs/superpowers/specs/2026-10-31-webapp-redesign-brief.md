# Webapp redesign — brief (shape)

Макет: `2026-10-31-webapp-redesign-mockup.html` (открыть в браузере; пульт справа внизу переключает состояние задачи и роль; `?job=done&calib=1&theme=light` — для скриншотов).

## Задача и пользователь
Владелец фермы FDM-принтеров запускает упаковку 3MF и ждёт результат 1–10 минут на той же странице. Режим поверхности — Operate: сканируемость, привычные паттерны, бренд в деталях.

## Что не так сейчас (критика текущего UI)
- Форма растянута на 1100 px сеткой 4 колонки: глаз ходит зигзагом, подсказки висят под полями разной высоты.
- Главное действие «Упаковать» — маленькая кнопка внизу формы; прогресс и результат появляются ниже, пол-экрана справа и снизу пустые.
- «Фаза 1 / Фаза 2» — внутренний жаргон; две строки шапки (бренд + вкладки) вместо одной.
- «Гостевой доступ» — кнопка-текст, ведущая во вкладку «Аккаунт», где смешаны вход, регистрация и сброс по токену.
- Тема переключается словами; заголовок «Goat Packer · упаковка и расписание» дублирует вкладки.
- Калибровка AMS — отдельный раздел, хотя её единственный выход — одно число в форме упаковки.

## Решения
1. **Шапка в одну строку.** Слева: знак + «Goat Packer» и разделы «Упаковка · Расписание · Мои задачи». Справа: иконка темы (солнце/луна), гость — «Войти» + меню (☰: гостевая сессия 24 ч, Мои задачи, Создать аккаунт); пользователь — аватар-меню (Мои задачи, Администрирование для админа, Выйти). Сброса пароля в меню нет. `<title>`: «Goat Packer — упаковщик 3D-объектов для печати с максимальной плотностью».
2. **Рабочий экран = две колонки.** Слева 340 px вертикальная форма (файл, профиль, раскладка, чистка, затем группа «окно печати» и «реальная смена прутка» с раскрытием, затем «Дополнительно»). Справа: строка действия (имя файла + «Упаковать»/«Отменить»), прогресс по этапам, результат, изометрическая сцена стола.
3. **Калибровка AMS** — без отдельного раздела: чекбокс «Учитывать реальную смену прутка» раскрывает поле «Смена прутка, с» и ссылку «Откалибровать заново…», которая открывает третью колонку справа (3 шага: сгенерировать тесты → напечатать → ввести время → «Подставить в упаковку»).
4. **Прогресс:** одна полоса, сегменты пропорциональны долям этапов (из `progressPercent`), текущий этап + «идёт / осталось», под ней список этапов; необязательные помечены «если понадобится», пропущенные — штриховкой.
5. **Мои задачи:** пункт меню → таблица (ID, тип, исходник, статус, создана, длилась) → клик по ID → `/jobs/:id` (сцена готового стола, файлы, параметры, тайминги этапов, «Повторить с этими параметрами»).
6. **`/login`:** одна карточка без придумок. Вход: логин, пароль с «Забыли пароль?» у поля и кнопкой «показать», «Войти», ссылка «Создать аккаунт». Регистрация: логин, email (необязательно, «скоро»), пароль ≥12 с «показать», без повтора пароля. Восстановление: логин/email → «Проверьте почту» (**заготовка**, письма не отправляются) + путь «Есть код от администратора?» → код + новый пароль (работает уже сейчас).
7. **Визуализация — гибрид.** Каркас: изометрический стол (кит `anatomy`, статичная фигура). Во время задачи — призмы реальных силуэтов на реальной высоте: проба режет 1 объект; раскладка — перебор (победителя ещё нет); сборка — реальные позиции падают от центра; нарезка — плоскость среза поднимается по проценту слайсера; проверка G-code — полоса проходит по слоям. В готовом результате и на странице задачи — настоящий меш (three.js, ортокамера, плоская заливка в палитре), вращение мышью.
8. **Тема:** токены, шрифты (IBM Plex Sans / JetBrains Mono) и иконки-спрайт из ozonware.

## Что нужно вне фронта
- Пакер: JSON-событие `{"event":"layout", bed, footprint_loops, height_mm, placements:[{x,y,rot}], keepouts, tower}` после этапа packing (и после repacking). Бэкенд прокидывает его в `GET /api/jobs/{id}`.
- Меш для результата: облегчённый (децимированный) меш объекта как артефакт задачи (glb/bin), а не исходный 3MF.
- Auth: эндпоинты `forgot`/email пока не делаем; фронт показывает заглушки.

## Границы
- Админка переносится как есть (только новая шапка).
- Локальный режим без аккаунтов: справа только иконка темы.
- Не меняем API параметров упаковки/расписания.

## Открытые вопросы
- Гостю нужно и «Войти», и меню ☰ — или достаточно «Войти» (Мои задачи уже в левой навигации)?
- Мобильная ширина: форма над сценой (как в макете) — достаточно?

## v2 (2026-11-01) — правки после ревью

Макет: `2026-10-31-webapp-redesign-mockup-v2.html` (пульт: состояние, роль, палитра A/B; `?printer=u1|a2l|p1s&palette=b&rail` для скриншотов; можно перетащить любую STL/3MF).

1. **Навигация — слева.** Сворачиваемый сайдбар с иконками (как в ozonware): Упаковка, Расписание, Мои задачи, у админа — Администрирование. Кнопка сворачивания в рейл — слева в шапке. В шапке справа только тема и аккаунт.
2. **Палитра — своя.** Два кандидата из styles.refero.design:
   - **A «Phosphor Instrument»** (Oxide, Zoox, Sauce Labs): тёмная `#0b0e12` + фосфорный `#00d892` (кнопки с тёмно-бирюзовыми чернилами `#002923`); светлая — мятно-серая `#edf4f2` + `#007a55`.
   - **B «Cobalt Schematic + Acid»** (Analogue aF-1, ClickHouse, Parallel, teenage engineering): кобальт `#2f55ff`/`#002fff` + кислотный лайм `#faff69`/`#e4f222` только как сигнал (прогресс, срез), никогда как текст на светлом.
   Контраст проверен (WCAG 2): A — акцент на фоне 10.4:1 тёмная / 4.8:1 светлая; B — 6.3:1 / 6.9:1.
3. **Шрифты.** IBM Plex Sans и JetBrains Mono — SIL OFL 1.1: свободно для коммерческого и публичного веба, встраивание и self-hosting разрешены; нельзя продавать сам шрифт и выпускать изменённый под тем же именем. Ставим через `@fontsource` (лицензия едет в пакете).
4. **Столы по профилю.** Рабочая область, отступ и зоны исключения — из `profiles/*.json` (уже есть: P1S `[0,0,18,28]`, U1 `edge_margin_mm: 4`). Добавить в профиль контур пластины `plate_outline` (10–40 точек). Сверка с слайсерами: Orca/Bambu `printable_area`, `bed_exclude_area` (P1S `0x0–18x28`), у A2L ещё `head_wrap_detect_zone`. Модели столов слайсеров (`bed_model` STL/SVG) — AGPL-3.0, их не копируем: контур рисуем сами по размерам. Сцена подписывает длину/ширину вдоль сторон, запретные зоны — белым (тёмная) / серым (светлая).
5. **«Учитывать реальную смену прутка»** — только внутри «Уложиться в окно печати»: без окна стол заполняется максимально и время не влияет на результат.
6. **Сцена — настоящая модель, любая.** Браузер сам читает загруженный 3MF/STL (zip + XML), строит меш и его проекцию-контур сразу после выбора файла. Во время задачи: проба режет один меш плоскостью отсечения; раскладка — перебор контуров; сборка — копии меша (instancing) падают на позиции из события `layout` пакера; нарезка — плоскость среза по проценту слайсера, срез подсвечен сигнальным цветом; готово — вращение мышью. Технология — three.js (ортокамера). `anatomy` для этого не подходит (рисует только свои выпуклые примитивы); оставить ему максимум декоративную иллюстрацию пустого состояния.
   В продукте контур — пакерский (силуэт/пятно первого слоя), позиции и повороты — из `layout`; браузерный контур — только предпросмотр до запуска.
