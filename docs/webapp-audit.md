# Аудит webapp, 26 сентября 2026

## Исходная ошибка

В пользовательском `goat3_v4.3mf` действительно есть `printer_model: Bambu Lab P1S`.
Старый endpoint `/api/profiles/detect` возвращал `{}`. `ZipInputStream` Java 21 падал
раньше чтения настроек на PNG-превью: `only DEFLATED entries can have EXT descriptor`.
Это корректный ZIP с STORED entries и data descriptors. `ZipFile` читает его central
 directory нормально. Исключение ранее проглатывалось и превращалось в ложное «нет принтера».

Исправленный HTTP-ответ на этот же файл:

```json
{"profileId":"bambu_p1s","printerModel":"Bambu Lab P1S"}
```

## Исправления

1. Общий Project3mf для загрузки/предпроверки pack/schedule: ZipFile, очистка временного
   файла в finally, ограничение размера чтения настроек, отдельные 400 для повреждённого
   ZIP/JSON, пустого файла и ошибочного multipart.
2. Явные nullable поля DTO вместо незаметно исчезающих ключей; осторожное однозначное
   сопоставление принтеров; проверка параметров локальных профилей и повторяющихся id.
3. Фронтенд показывает настоящую ошибку запроса, а не объявляет каждый сбой отсутствием
   printer_model. Предыдущий запрос определения отменяется; ответы старого файла не
   перезаписывают новый выбор. Повторный выбор того же файла работает.
4. Вкладки сохраняют формы, задачи и результаты. Нет окна повторной отправки между 202
   и первым статусом. Обработчики submit проверяют те же условия, что и кнопки.
5. UI отмены задач, cancellation token и синхронизация старта процесса. Удалённая задача
   из очереди больше не запускается. Снимок дочерних процессов сохраняется до завершения
   родителя, чтобы не оставить осиротевший слайсер. При завершении приложения задачи
   отменяются. TTL не убивает активные/ожидающие задачи; старые orphan-каталоги убираются.
6. Планировщик проверяет профиль/источник и не принимает одновременно file + packJobId;
   queued schedule владеет собственной копией входного файла. Исходную pack-задачу можно
   удалить после создания расписания, не ломая его выполнение.
7. Выдача work/placements.json, журналы ошибок на фронте, запрет скачивания ещё не готовых
   результатов и выхода через symlink за каталог задачи. Ошибка отсутствующего артефакта
   сохраняет понятную причину, а не заменяется произвольными последними строками лога.
8. Проверки времени 0..47 и порядка день < ночь < горизонт, чисел и параметров очистки.
   `global,every=1` больше не превращается в `global` с CLI-дефолтом every=10.
   Дублирующийся every и переполнение интервала отвергаются.
9. Убраны устаревшие seed/candidates-настройки UI случайного поиска; API сохраняет
   совместимость, seed по умолчанию стабильный.
10. Исправлены CORS для localhost/127.0.0.1 с настраиваемым конечным списком origins,
    отображение исчезнувшей после рестарта задачи (404), перекрытие подзаголовка заголовком.

## Проверки

- **69 backend-тестов**, `./gradlew --offline test`: проходят.
- **8 frontend-тестов** (`bun test tests`): проходят.
- `bun run typecheck`, `bun run lint`, `bun run build`, `./gradlew --offline bootJar`: проходят.
- Новые проверки: синтетический STORED+descriptor ZIP, явные null, повреждённый архив,
  отсутствие multipart-файла, очистка every, queued/running cancellation, TTL,
  самостоятельная копия scheduler input, запрет ранней выдачи/ссылок за каталог.
- Старые тесты валидации использовали невалидные байты вместо 3MF и могли проходить
  не по той причине. Их входы заменены самостоятельными синтетическими проектами.
- Браузер: исходный пользовательский файл определён как P1S, кнопка упаковки активна;
  пройден pack → успешный результат → переключение вкладок без потери → передача в
  расписание → успешный schedule и артефакты CSV/XLSX/3MF.
- Browser smoke выполнен на отдельном backend19191/frontend3010 с **фейковыми CLI**:
  числа 30/63 в тестовых результатах не являются расчётом плотности/расписания для файла
  пользователя. Реальный слайсер не запускался. Проверка формата исходного 3MF — настоящая.
- Все регрессионные тесты самостоятельны: пользовательский Downloads-файл нужен только
  для ручного подтверждения, не для тестового набора.

Скриншот проверки реального файла: [webapp-profile-check.png](webapp-profile-check.png).
Тестовые серверы после проверки остановлены; работающий пользовательский backend на19190
не перезапускался. Для применения исправления его нужно перезапустить с новым кодом.

## Границы проверки

Это проверка основных API и пользовательских сценариев, не доказательство отсутствия
всех возможных ошибок. Реальная печать/длительный слайсинг, длительная нагрузка и восстановление
задач после рестарта не проверялись. Хранилище задач по текущему дизайну остаётся в памяти;
полная перезагрузка страницы также сбрасывает локальные формы. Коммит не создавался,
предыдущая оптимизация Rust и несвязанные существовавшие изменения сохранены.
