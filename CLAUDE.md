# CLAUDE.md

2D irregular-nesting packer for FDM printing: packs the real flat-bottom silhouette of a mesh (not its bbox) and rebuilds a slicer 3MF project from the layout. Second tool benchmarks slice times and schedules a 24h multi-printer run. Rust 2024, plain `std` + rayon/serde/zip/quick-xml/geo/tiny-skia; webapp in `webapp/` (Kotlin + React, см. `webapp/README.md`).

## Commands

```bash
cargo build --release
cargo test --release --all     # release is required: packing tests are slow in debug
cargo test --release colored_pack   # by name substring
```

CI: Woodpecker `ci.ezheg.xyz` (`.woodpecker/`): `check` on every push, `release` on tag `v*` builds `goat-packer-*:<tag>` into Docker on `main` via `deploy/build-images.sh` (the only description of the image build; no registry).

Tests must stay self-contained: generated temp data or `tests/fixtures/` only (printer profiles too: `tests/fixtures/profiles/`, generic test beds — tests never read the `profiles/` catalog or name its printers, except the one check that every catalog profile loads with a unique id/name); no sibling-dir paths, symlinks, env-gated no-op tests, shared `/tmp` names. The packer and tests never call a slicer or network; the production colored-3MF pipeline does (slicer path comes from the printer profile).

## Packing core (`src/packing.rs`, `src/packing_search.rs`, `src/raster_mask.rs`, `src/collision.rs`, `src/validation.rs`)

Module map: `geometry` (Point/Rect/loops), `footprint` (+ `stl`, `gcode_footprint` build it), `span_raster`/`pixel_mask`/`raster_mask` (pixels per angle), `collision` (zone pairs, bed, exclusions), `packing`/`grid`/`packing_search`/`frame` (the search and the lattice baseline; the grid tries every row shift, so shaped models tile in brick rows), `validation` (`validate_result`), `options` (`PackOptions`, `PackResult`). `lib.rs` only declares modules and re-exports the public API. G-code vocabulary and arc maths shared by the readers live in `gcode_text`.

The production path packs through `pack::pack(prints, rules, tower, options)` over one `ObjectPrint` per rotation class (`object_print` kinds, `keepout` matrix, `kind_masks`, `validation` incl. `validate_vector`; design `docs/superpowers/specs/2026-11-02-slicer-free-packer-design.md`); `pack_footprint`, `grid_layout` and `validate_result` serve the legacy `Footprint` tests and tools.

- `pack/improve` (member `Improve`, runs after every other member, `--effort`-scaled by insertion origins per round, never by wall clock): takes the best layouts of each member in turn (`top_sources`), inserts a copy at the least-overlap origin of a plate-wide cost map and resolves the overlaps with guided local search on raster penetration depth (`separate`; all copies mobile, only overlapping ones move; no RNG), accepts only after the exact no-fit check; a stalled layout is compacted into each corner and searched again. Windowed variants (corner/edge/tower, only the copies in the window mobile) were measured worse and slower: do not bring them back (P1S 48 vs 49, U1 59 vs 60, A2L tower-corner plate 77 vs 79). `pack/robustness` measures the Chebyshev slack of a layout (pairs and tower) into `RankKey::robustness_quarter_mm` (ranked right after the count); `improve::polish` pushes the top layouts apart by growing the no-fit sets by 1, 2, ... px and separating again, so spare room is spent on safety. Improved layouts are `Member::Improve` candidates whose `detail` = source member, source count, source detail (polished: source member, count, -1, ...).
- Resolution ladder (`pack/ladder.rs`, `PackOptions::resolutions`, `--resolutions 0.25,0.2` default since 2026-11-04, `0.25,0.2,0.15` opt-in: on the full pipeline at two threads 0.15 mm never added a copy (U1 55/56/56, P1S 45/46/46, A2L 79/77/78 at 0.25/0.2/0.15) and was the slowest level; `--resolution X` = just X): the same run (own `Ctx`, members, raster + vector check) at coarse then finer rasters, best by the rank key (finer replaces only on strictly more copies, then slack, then box in mm²), so a finer ladder never returns fewer. Finer levels run only the lattice family + `Improve` (Sweep/Rows trail 2-5 copies at every resolution). Evidence (goat bench, locked rot000): U1 58/59/59, P1S 47/47/47, A2L 77/77/78 at 0.25/0.2/0.15; pipeline U1 55 -> 56, P1S 47, A2L 79. Levels run sequentially (A2L at 0.15 mm ~380 MB for one pack; the whole run peaks ~0.9 GB). `colored_3mf_packer` packs every foreign-gap rung at the first resolution, then `pack::refine` climbs the finer levels only for rungs within `gaps::REFINE_SLACK` (1) of the best coarse count: climbing all rungs took A2L 20 s -> 84 s for no extra copy; now U1/P1S/A2L pack in 8/8/20 s coarse and 32/25/31 s total.
- Upper bound (`pack/bound/`, Oler / Folkman-Graham normed form: `area(D)/Δ(C) + perimeter_C(D)/2 + 1`; `C` = inscribed symmetric polygon in the no-fit region, `Δ` its critical determinant, `D` = hull of feasible origins, tower ignored): per class and for any mix (`PackOutcome::{upper_bound, class_bounds}`, report `upper_bound`, progress line), 20-50 ms. It is a raster-level ceiling (U1 66, P1S 55, A2L 90 at 0.25 mm vs 59/47/78), loose for goats (their densest lattices are diagonal) and much looser for mixed classes (0/180: 72/64/108); members get it as the object cap and a level at the bound ends the ladder. Never a target; not a proof for the continuous plate.
- Search is deterministic; `seed`/`candidates`/`stall` are compatibility fields, not random controls. More effort extends a prefix, never discards an earlier winner. Rayon only parallelizes independent angle families.
- `validate_result` must stay independent of the search's no-fit maps (it re-rasterizes and then checks original-coordinate vector geometry in `validation_geometry`). Conservative raster coverage includes boundary-crossed cells; clearance uses square dilation (the old discrete disc under-reserved diagonal gaps). Body zones have independent bounds; body/body is always checked; every known height participates in bed bounds. `verify_outputs` is a further independent check (`geo`, exact geometry) sharing no packing code: use it as second opinion on any layout change. It covers clearance between mesh silhouettes/bodies, keepouts, margins, transforms; it does NOT check `--support-overlap-mm` (support cores are only checked by `validate_result`).
- Heuristic at finite resolution, not an optimality proof. Tradeoffs: `docs/packing-search.md`.
- `support_overlap_mm` (`--support-overlap-mm`, `None` = unlimited): a third no-fit pair of support cores (printed patch eroded by X/2 per side: erosion radius `floor(X/2/res)` pixels, coded as `ceil(-X/2/res)` in `support_core_radius`, i.e. rounded toward less erosion) so printed supports of neighbours overlap ≤ X mm (0 = may touch, never overlap) while bodies keep clearance; grid and `validate_result` check it too. Cores are only built when `Some` and body ≠ full, so the default path and bodyless footprints stay byte-identical.
- Pair rules over kinds are one table (`keepout/matrix.rs`; `verify_outputs/rules.rs` keeps its own copy on purpose and a test pins both): silhouettes keep `--clearance`; a support base vs a neighbour's landing keeps `ForeignGaps::base_mm` (default `SUPPORT_BASE_GAP_MM` = 0: may touch, never overlap: the owner's printed-OK plates have bases touching neighbours' first layers at −0.04..−0.09 mm, supports fused to each other, never to a goat); supports above layer 0 and interfaces vs a neighbour's `body[k]` keep `ForeignGaps::band_mm` (default `SUPPORT_BODY_GAP_MM` = 0.5; the tower body follows it) in the same 2 mm band. The foreign gaps are runtime values (`PackOptions::foreign_gaps` -> `MaskRules`/`LayoutRules`, `Gap::mm(clearance, foreign)`), packer-only, never in the 3MF; `verify_outputs` has `--foreign-base-gap/--foreign-band-gap` with the same defaults and its pinning test also compares non-default values. So `ObjectPrint::support[k]` holds only the layers ABOVE layer 0 (`Realization::above_base`): with the base in band 0 the 0.5 mm band rule would test it against the neighbour's whole `body[0]` and the zero base gap would never apply. Band rule (`object_print::layer_bands`): a layer occupying (z_prev, z] feeds every 2 mm band it overlaps with positive length; `realization_from_gcode`, the tower chamfer rings and the masks share it. Tower zones (`pack/tower.rs`): the column and the chamfer rings of layers ≥ 1 are `TowerBody` (z-ranged, design §4.2/Q18: supports keep `band_mm` from them); only the layer-0 brim is a brim zone. It is `TowerBrimChecked` (supports keep out, gap 0) when the target GUI's G-code path-conflict check compares tower brim loops (`Flavour::conflict_tower_lines` != `None`: Bambu and Snapmaker Orca; the owner's U1 plate got "Serious warning ... WipeTower <-> goat" in Snapmaker Orca 2.4.0 from a corner goat's support base over the brim while the vanilla-Orca CLI passed, because Orca's type-2 tower records no lines), else `TowerBrim` (supports may overlap). `gui_checks` reproduces the same rule per flavour (`GuiRules::tower_lines`); behaviour in `docs/superpowers/specs/2026-11-03-gcode-conflict-check.md`.
- geo's `unary_union` takes its fill rule from the FIRST ring's winding and drops rings wound the other way: orient polygons before mixing sources (`union_exterior_loops`).

## Support model (`src/support_model/`, `colored_3mf_packer --support-source model`)

Clean room (design §1): the Bambu/Orca/Snapmaker organic tree-support behaviour is reproduced from the behaviour specs in `docs/superpowers/specs/2026-11-02-organic-support-spec/`, in our own structure and names; never translate slicer code, never mirror upstream identifiers, comments or control flow (the sources under `/tmp/goat_src` may be read only to settle a behavioural question). Stage A (`stage_a`, once per mesh/settings/flavour/rotation): `layers`, `sections`, paint (`crate::paint`), `overhangs`, `clearance` volumes; unsupported settings fail before any geometry (`SupportError::Unsupported`, design §5.7). Stage B (once per ensemble member, single-threaded, `Vec`/`BTreeMap` only, `libm`): `tips` (outset rounds, roof stacks, line pattern in `tips/lines`, `tips/resample`) -> `descend` (influence areas: `speeds`, the stepped offset `soi`, the trial order of `settings`, `evaluate`) -> `merge` (box-tree order, bucket rounds, pair test) -> `place` (lazy placement from the roots up, compaction) -> `smooth` -> `draw` -> `base` -> `bands` (one `Realization` under the band rule). The order rules (`merge/order`, `merge/rounds`, `place`) are pinned by the recorded vectors of spec 02 §8.
- The roof tip lines run at `Flavour::roof_line_angle_degrees`: 135 degrees for Bambu (spec 01 §5.5), 45 degrees for Orca/Snapmaker (the spec's 135 is wrong there: on deterministic vanilla Orca slices the feet match 11 % better, on the Snapmaker GUI plates the largest miss falls 1.53 -> 0.95 mm (L1) and 2.65 -> 1.94 mm (bands); Bambu loses 30 % at 45).
- `draw` slices every branch as FINITE cylinder pieces at each layer's mid-height (plus a ball at a merge or a sharp bend): the endless ellipse of a branch that jumps sideways between two layers was metres long and put a 7 mm blade into band 0. A flat first layer root is a disc (Orca) or a hemisphere cut (Bambu, Snapmaker).
- `ensemble`: every thread class of the merge bucket rule (found EXACTLY by speculative runs; a run at T makes the decision `floor((n+2)/4) >= T` per merge, equal decisions = one class, so the classes tile 1..inf) x every arc-connector family (S9; R has one) x the merge-order reading axis (`MergeOrder::{Along, Against}`; the default is `Along` only: the spec's order vectors fix a permutation but not whether the slicer's list runs along it or against it, and with the roof lines at the build's own angle `Against` adds ~7 % area without moving the worst miss; `--support-orders along,against` runs both) x the overlap reading of the pair test (`merge::Overlap`, erosion 0.025 = the slicer's own, 0.1, 0.2, 0.4, 0.8 mm: marginal merges, where two influence areas only touch, flip on rounding/platform/thread count and move a whole foot by 2-5 mm; no single threshold fits, their union covers the slicer). A graph an earlier member drew is not drawn again (`MemberRun::realization` is `None`; which member draws it depends on timing, so `distinct` orders by the first member). `predict` = stage A + ensemble + the SHA-256 `cache` of the raw distinct realizations (bump `MODEL_VERSION` with EVERY behaviour change); `envelope` = their union (holes filled) grown by the flavour's margins.
- Margins live in `flavour.rs` (`first_layer_margin_mm`, `band_margins_mm` per absolute band) with their evidence: δ = the largest exceedance of any recorded realization outside the model's ensemble union at rotations 0 and 180 + 0.1 mm (campaign 2026-11-03: `examples/support_corpus.rs`, observations = CLI and GUI single-object slices and the printed-OK plates, object matched by its printed first layer). They are MODEL error, not slicer noise: B (P1S, A2L; 34 observations) L1 2.30 / bands 5.05 mm, S (the owner's Snapmaker GUI plates, 8) 1.61 / 2.65, R (vanilla Orca CLI, deterministic, 10) 3.50 / 6.46; the misses are a few discrete merge decisions (two trunks the slicer keeps apart, the model merges), mostly at 180 degrees. `--support-margins L1:BAND` replaces them, `--support-orders` picks the order readings. B recalibrated 2026-11-04 with the overlap readings over 133 observations (macOS slices at 1-20 threads, Linux runner slices at 1-20 threads, old CLI and GUI runs; P1S and A2L at 0/180): L1 0.51, bands 1.48..2.31..0.74 mm (was 3.6 / 5.47); S (and O) over 40 Snapmaker Orca 2.4.0 slices at 1-20 threads: L1 0.77, bands 1.48..1.99..0.49 (was 1.7 / 2.23; the owner's printed 48-goat GUI plate lies 0.06 / 0.71 mm outside); R keeps the 2026-11-03 values.
- Bambu Studio 02.09.01.70 (`Flavour::Bambu0209`, `bambu-02.09`, the owner's GUI and the server image since 2026-11-05) is modelled exactly as 02.08 with its own margins: L1 2.48, bands 3.16, 2.79, 4.26, 4.44, 4.13, 2.98, 1.99 .. 0.74 mm over 161 single-goat slices (P1S/A2L at 0/180; macOS 1-20 threads + repeats at 14, 119; Linux x86 in docker 1-20 threads, 42). Its misses are systematic, not thread noise: next to 02.08 at the same T the supports above ~12 mm are identical, below it 02.09 lands fewer, differently merged feet (worst L1 2.38 A2L 180°, band 0 3.06 A2L 0°); bands 2-4 come from ONE Linux race (P1S 0° T=16, a trunk 4 mm off; without it 2.58/2.18/1.78, counts +1). Tried and dropped: Along+Against (L1 2.40, 3x time), extra pair-test readings 1.6/3.2 mm (L1 1.13 but union +28 %, 10x time; P1S/A2L 38/65). Counts with 02.09 margins: P1S 36, A2L 64 (02.08: 44/72; printed-OK 43/70), both plates sliced clean by the 02.09 CLI (no `--no-check`) and `gui_check` at T=1/4/8/14/20. Corpus: `/tmp/goat209c` (`*.jsonl`), Linux `LD_PRELOAD` fake in `~/goat209lin/fakecpu.c`.
- Version resolution (`Flavour::resolve`): a Bambu project saved by an older or the same build than the profile's `gui_flavour` is sliced in the profile's build (the owner's projects say 02.08.02.61 and are sliced in 02.09); a newer or other uncalibrated version maps to `Flavour::NEWEST_BAMBU`, `approximated`, and `ResolvedFlavour::margins` then takes the widest margins of every calibrated build of the family per band (Orca/Snapmaker too); the packer prints `warning: slicer version X not calibrated; using the widest margins` and repeats it in the report's `warnings`. A new Bambu build = a new variant, its `bambu_version`, margins from a corpus, `NEWEST_BAMBU`, `BAMBU_GUI_VERSION` in `printer_catalog/rules.rs` and the profiles.
- Tree supports depend on the slicer's thread count T = `tbb::this_task_arena::max_concurrency()` (the logical CPUs; the GUI never limits it), on run-to-run races (spec S1: 12 macOS runs at T=14 gave 3 trees) and on the platform (Linux x86 and macOS arm differ at the same T). A server CLI slice that is clean proves nothing for a user's machine: the v0.6.1/v0.6.2 P1S 46 plates passed the server check and conflicted in every macOS slice. Corpus tooling: a re-signed BambuStudio copy with `DYLD_INSERT_LIBRARIES` interposing sysconf/sysctl(byname) fakes T on macOS; on Linux an `LD_PRELOAD` must also intercept the raw `syscall(SYS_sched_getaffinity)` (TBB is static). `examples/support_classes.rs` lists the model's members, `examples/gui_check.rs` runs `gui_checks` on any G-code. The Snapmaker Orca 2.4.0 CLI on macOS slices once two GUI-only calls are stubbed with `ret` in an ad-hoc re-signed arm64 copy (`PartPlate::generate_plate_name_texture`, `expand_plate_extruders`, which reach a null `GUI_App`); its goat patch then matches the GUI (46.1 x 41.9 vs 46.5 x 42.4 mm) and it reports path conflicts by exit 155 like Bambu (a goat moved 4 mm into its neighbour failed). Corpus only, never shipped.
- Not modelled / known gaps: the connector's full arc selection (`tips/lines` chains neighbouring chords by serpentine arcs; S9 only changes which arcs are cut), upstream's AABB-order direction (above), B's 225 degree supports at z 26-41 mm (`bands max` 1000 in the campaign rows: rotations beyond 0/180 are not calibrated), sharp-tail roofs 2-3 layers short at z ~20 mm (stage A), bed clipping and B's bed-edge obstacle (the canonical copy is assumed interior: `order::canonical_first`). `examples/printed_ok_check.rs` validates the owner's printed plates against the envelope: the union is stricter than the single realization that printed (P1S 43: inadmissible at delta 0, base vs landing and band 11), so "printed plates stay admissible" cannot hold for a union of this size.
- Tools: `examples/support_corpus.rs` (campaign; `--single T family` runs one member), `examples/support_graph.rs` (graph, timings, `DUMP_REGION`, `DUMP_JUMPS`, `--` tip dump), `examples/printed_ok_check.rs`. Tests: `tests/support_model.rs` (cantilever graph, class tiling, determinism for 1/3/8 threads, cache, unsupported settings), `tests/support_stage_a.rs`.

## Printer profiles / slicer quirks (`src/colored_packer/`: `profile.rs`, `cli_settings.rs`, `prime_tower.rs`)

- `PrinterProfile` (`profiles/*.json`) is the only source of printer geometry; never hardcode it. New printer = new JSON, not a code branch.
- Plate zones come from the profile's `bed_rules` (`colored_packer::bed_rules::plate_rules` -> `PlateRules`; classes hard / restricted / soft; what a class forbids lives in `keepout/matrix.rs`, never in profile data); a profile without it goes through the legacy table. `body_edge_band_mm` binds model part boxes, `print_edge_reserve_mm` supports and tower material; `--edge-margin` overrides the body band. Evidence kept from the old `support_edge_margin_mm` (still in the profile for the webapp and `source_project`): U1's 4 mm margin on the 47.6 mm goat patch held the packer at 45 while a hand-made plate printed 48 with supports 0.7 mm from the edge and meshes 3.7 mm off it.
- `SLICER_KEEPOUT_SAFETY_MM = 4.0` is empirical (false "gcode path conflicts" on dense plates). Don't lower it from a single-object test.
- `slicer_kind` is inferred from `printer_model`, not 3MF `Application` metadata (Orca forks still say BambuStudio).
- No prime tower (`parse_prime_tower_bounds` -> `None`) is legitimate, not an error.
- Slices are read in plate coordinates: BambuStudio writes G-code minus the project's `extruder_offset` (P1S `0x2`) and its GUI adds it back before the "G-code path goes beyond plate boundaries" check (CLI has no such check). `slice_project` shifts every slice (`gcode_frame`); keepouts declared in the G-code frame (`frame: gcode`: the start G-code's purge lines) move by the same offset once, in `plate_rules`.
- Tower anchor range per slicer build (`tower_model::anchor_range`, in `TowerSpec::anchor_range`): BambuStudio's GUI re-clamps the stored tower on open to [15 mm, bed − GUI estimate − 15 mm]; Snapmaker Orca on every scene reload to 1 + `prime_tower_brim_width` against the real depth; OrcaSlicer 2.5's CLI snaps anchors within 5 mm of its range; 2.4 keeps them. `pack::pack` chooses the anchor inside the range (no tower contest, no free-spot step) and `wipe_tower_x/y` is set to it. The GUIs still move a corner tower on open (owner, 2026-11-03: Bambu Studio and Snapmaker Orca on the packed P1S/A2L/U1 plates); dragged back to the packer's corner it slices clean, so the webapp warns the user (`TOWER_GUI_WARNING`) instead of fighting it. `plate_centre::gui_tower_anchor_range` is the estimate-only fallback when the tower model refuses a project.
- Tower shape is forced (`--tower-width MM|keep`, default 20, webapp «Ширина башни»; `tower_model::force_tower_shape`): `prime_tower_width` and, for Bambu, `prime_tower_rib_wall = 0` go into the job's settings (model), the probe copies and the output 3MF (`tower::apply_tower_shape`, the second exception to byte-for-byte settings). Depth stays the slicer's: purge over width, at least the depth by tower height (P1S Saving: 20 and 30 mm wide both 11.2 mm deep). The purge mode is never touched: Bambu's GUI resets Saving to Default only when its printer model changes on load (`GUI/Tab.cpp:5906-5916`; hidden button on single-nozzle printers, width-20 tower then 25 mm deep), and writing "Default + every filament_prime_volume = 15" (same tower) makes the Bambu CLI report WipeTower <-> goat conflicts 12 mm away (02.08 and 02.09, 4/4 runs; Saving 3/3 clean).
- Snapmaker Orca's "Disable spiral lifting or keep 3.5 mm gap" warning is a bbox-to-plate-edge check (< 3.5 mm), not a lift-type check: no z-hop setting clears it; the U1 profile's 3.5 mm body margin is exactly its limit. Details and the tower-vs-support conflict analysis: `docs/superpowers/specs/2026-11-03-gcode-conflict-check.md`.
- Every slicer call goes through `slicer_cli::slice_command`, which passes `--arrange 0`: without it Orca re-arranges the plate on slice (25 of 38 sliced on U1). BambuStudio takes the same flag; don't narrow it to `slicer_kind = orca`.

## `colored_3mf_packer` (`src/bin/colored_3mf_packer/`) invariants

One module per pipeline step: `args`, `job` (profile; `bed_rules` -> `PlateRules`; target flavour = the project's `Application`, else the profile's `gui_flavour`; `ObjectMesh` of all normal parts and the source item transform `ItemFrame`), `model` (per rotation class `probe` -> `class_print`, plus `tower`), `prepare` (`arrange`: `pack::pack`, centre-out and canonical-first `order`), `assembly`, `report` (state and report), `verify` + `learn` (only with `--verify`), `time_window` + `time_report`, `slicing`, `source`, `probe_cache`, `margins`, `loops_ops`. The default job slices no plate: the plate is predicted from probes of one object.

- `--support-source auto|probe|model` (default `auto` since 2026-11-04: the model, and probes only when the model refuses the project's settings (`SupportError::Unsupported`: raft, normal supports, unreadable settings; a progress warning and `warnings` in the report); any other model error stays an error; the report's `support_source` is what was used. Probes see only the thread class and platform of the machine that slices them. The model path is `from_model.rs`: supports from `predict` + `envelope` with the flavour margins, landing from `first_layer`, tower from `tower_model` only, ZERO slicer calls; the report carries `support_source`, `model_seconds`, `margins_mm`; the first-layer gap the job forces is fed to the model like to the probe copies). Counts on the owner projects, 2026-11-03 (U1 / P1S / A2L; probe mode 56 / 47 / 79): model, margins 0:0 55 / 47 / 80; model, 0.5:1.0 53 / 46 / 79; model with the margins calibrated before the 45-degree roof-angle fix 48 / 35 / 62 (each verified by ONE slice (`--finish-state`; no support/body contacts, no repack, gui checks passed; the U1 plate was sliced by vanilla Orca, not the Snapmaker GUI); with the final Along-only margins (max exceedance + 0.1 over 70 B / 40 R / 8 S observations: L1 3.6 / 5.0 / 1.7) 51 / 34 / 61 (unverified by slice); Along-only margins 0:0 56 / 47 / 81. The gate on counts failed then. 2026-11-04 with the overlap axis and the recalibrated B margins: P1S 44 / A2L 72 / U1 48 (the owner's printed plates: 43 / 70 / 48); all three plates sliced clean at 1-20 threads on macOS (Bambu 02.08.02.61, Snapmaker Orca 2.4.0). The first slice of every small-margin (0.5:1.0) plate found layer-1 path conflicts and repacked (net 52 / 45 / 79), so small margins are not safe without `--verify`. P1S counts by margins (first layer : band): 2.4:0.5 40, 0.5:5.15 35, 1.0:2.0 42, 1.5:3.0 41; the band margin costs most.
- Supports come from probes. For each class in `--rotations` (default `0,180`) the source object, turned by the class angle about its frame centre, stands alone at the bed centre (interior: nothing is clipped or bent) in a copy written by the same `assemble` as the final plate, and is sliced sequentially (one live slicer) at least 3 and at most 8 times; the probe stops once 2 consecutive runs add < 1 mm² to every band. Tree supports differ between slices (multi-threaded; the user's GUI slices on all cores), so the union of `realization_from_gcode` over the runs stands for the family; one of five goat probes once lost a whole support foot, so never go back to a single run. `ObjectPrint` = mesh kinds (`mesh_section`) + landing (first-layer model ∪ printed first layer, cross-checked in the report) + `support_base` grown by `DELTA_FIRST_LAYER_MM` and `support[k]`/`interface[k]` by `DELTA_BAND_MM` (`margins.rs`: start values with their evidence; replaced from the calibration report). Cache (`--cache-dir`): the key is the SHA-256 of all part meshes and paint, the item transform, the whole project settings, the slicer binary (path, size, mtime), the rotation, the probe position and `MODEL_VERSION` (bump it when what a probe stores or how G-code is read changes); a hit runs no slicer. The raw measured unions are cached, not the grown prints, so changing a δ needs no re-slice.
- Tower: the union of the probes' towers per layer (`gcode_collisions::tower_layers`, arc aware; the column is the upper half of the layers as `gui_checks` reads it, the first layer's excess is the brim, a lower layer's excess a chamfer ring) merged with `tower_model` for the TARGET flavour; the larger wins (U1's vanilla-Orca probes print 9.5 mm of depth, the Snapmaker GUI 16.1). A tower appearing or missing only in a verification slice is a hard error; a wider one is learned and repacked once.
- One realization per class: the copies of a class share one support set and the slicer clips by the FIRST copy. `order::canonical_first` puts the copy with the most clearance from the bed edge, hard zones and tower first in its class (BambuStudio routes branches around the bed edge as an obstacle; the report flags `canonical_near_edge` under `BAMBU_OBSTACLE_MM`). Centre-out ordering runs first, so a window prefix holds each class's canonical copy. `assemble` never duplicates meshes per object, which keeps that rule.
- Supports across the bed edge (`bed_rules.max_support_clip_mm`, `PlateRules::support_clip_mm`, `keepout::clip`; opt-in, absent = 0, capped by `GuiFlavour::support_clip_cap_mm`: Bambu 4.0 from the owner's P1S GUI plate, where 3.96 mm of every goat's support at the top edge was cut and printed clean; Orca/Snapmaker 0: their sources clip too but no printed plate confirms it). The clip is taken in the FIRST copy's frame (`m_machine_border` translated by `instances().front().shift`), so a crossing layout is safe only if the first copy crosses every edge as far as any other copy: `canonical_first` then picks that copy instead of the interior one, `PackPlan::validate` checks it, a layout without one is refused. One open edge is always satisfiable, so `prepare::clip_configurations` packs supports-inside plus each single edge (5 passes) and keeps the largest valid layout. Measured 2026-11-03 with the cap on: P1S 47 -> 47, A2L 79 -> 79; all four edges open reaches 49 on P1S but no copy dominates (left 1.4, top 2.3, right 3.7 mm on different copies). Gap checks with the unclipped envelope stay conservative for the cut itself, but Bambu also routes the first copy's branches around the bed edge (`support_model::clearance::bed`): an edge first copy prints a bent realization that is not a subset of the interior one, so only a verification slice proves such a plate.
- Collision geometry comes from the mesh embedded in the source 3MF (`embedded_mesh::load_object_mesh`: every volume, item transform applied, frame origin = bbox centre of the normal parts), never a separate STL (a drifted STL silently invalidated collisions). A clone's build-item transform is `assemble::ItemFrame::clone_transform`: the source item's transform, then a Z rotation about the frame centre, then the move to the placement (the old rotation-plus-translation transform dropped a source rotation); `assembly` also writes `embedded_source.stl` and a legacy-shaped `placements.json` for `verify_outputs`, the webapp and the catalog qualifier.
- `assemble` uses the default mesh mode, never `reuse_source_object_instances` (triggers "gcode path conflicts"). `project_settings.config` is copied byte-for-byte (single exception: `wipe_tower_x/y[0]` set to the anchor `pack::pack` chose, `plate_centre::relocate_wipe_tower_in_3mf`); `paint_color` lives in the mesh, so coloring survives. `PackPlan::validate` (`validate_vector`) checks every plate before a 3MF is written, resumed states and window prefixes included.
- `<output>.state.json` (version 2: prints per class, rules, tower spec, placements in 3MF order) is written by every run; a version 1 state (slicer-learned footprint) is refused with a message. The report carries `final_sliced: false`, `support_source: "probe"`, probe runs per class, margins, tower anchor, canonical indices and per-class counts.
- `--verify` (implied by a time window and by `--finish-state`) slices the assembled plate and checks it: `analyze_plate` (labelled-object coverage, support lines vs foreign body lines per layer, material past the bed with half widths), `gui_checks::check_plate` (GUI-equivalent bed, exclusion and path-conflict rules) and the tower box against the reserved one. A failure learns the realized geometry into the class prints (`learn`, grown by the same δ) and packs again ONCE; anything left is fatal: never publish a successful verification with remaining collisions. Missing or incomplete labels are fatal too, including time-window slices. `--no-final-slice` is an accepted no-op. Webapp: «Сразу проверить нарезкой» (off by default) = `--verify`; «Проверить нарезкой» runs `--verify --finish-state` INSIDE the same job: an internal child queue row (`parent_job_id`; parent's `check_job_id`; state promoted to `finishStateBlobId`, server-set only) that the user never sees — same URL and list row, the parent's status carries `check` (status, stages, result, parent-scoped artifact URLs) and the child's layout. `POST /api/v2/jobs/{id}/check` (local: `/pack/jobs/{id}/finish`); a failed check leaves the packed plate downloadable and can be re-run. Pack stages keep a span `history` and are returned after the job ends («Инфо»).
- Progress: `progress::stage` prints the human line plus (with `GOAT_LOG_FORMAT=json`) a `{"event":"stage",...}` event; `bounded_output` adds a `slicer_progress` heartbeat every 2 s. Stage ids are mirrored in the webapp's `ProgressTracker.kt`/`PackStage.kt`. Long stages send sub-steps (`progress::stage_step`, `detail` = `StageDetail`: `step`/`steps` plus, for `probe_slice`, rotation, run, min/max runs, cached; for `packing`, phase coarse/refine, gap variant i/n, resolution level); the backend merges consecutive events of one stage id into ONE span (window slices excepted) with a live Russian sub-label (`StageLabels`) and a span `note`, and moves the bar by steps. The first line `{"event":"plan","stages":[...]}` lists the stages the run will enter (plate slice and its check only when it verifies), so «этап N из M» and the pending list never promise a slice the default job does not run.
- Centre-out (`--time-window-hours`, opt out `--no-centre`; `src/plate_centre/`): placements are ordered by distance from the smallest (by area) `heat_zones` centre and the window keeps a prefix. The tower is NOT moved to the centre any more: `pack::pack` chooses the anchor (a target-anchor option for window plates is open work). No window = no reorder.
- `prepare_cli_copy` (and `ams_calibration`'s CLI copy) use `colored_packer::apply_cli_settings_workarounds`: resizes `flush_volumes_matrix` to `filament_colour.len()^2` and optionally blanks `machine_start_gcode`; Orca CLI rejects mismatches. Blanked start G-code means U1 estimates (and the time window) exclude the start sequence; `--prep-min` must cover it.
- Time window (`--time-window-hours`, always verifies): first aim = line through the time probe (1 object, the first class's probe copy, with the same `--nozzle-clean` injection) and the max plate; every shrink after an overshoot uses the secant through that window plate and the max plate (both sliced from the output with identical settings), not the probe line. Each window prefix passes the same checks as a verified plate (`PlateRun::check`).
- `--nozzle-clean` (`src/nozzle_clean.rs`): wipe body is profile-owned (`nozzle_clean_gcode`); absent field = unsupported, explicit error (A2L has no hardware-validated sequence). Details: `docs/superpowers/specs/2026-09-02-nozzle-clean-injection-design.md`.
- Three distinct gaps (`gaps.rs`). OWN (support vs its own model) is the slicer's, from `support_object_first_layer_gap` / `support_object_xy_distance` of the project: read once in `Job::own_gap`, reported as `own_support_gap`, and `build_colored_project` fails if the output 3MF's settings differ (tower rewrite, nozzle-clean); not iterated (each value needs new probes for no density gain). Who sets the first-layer gap (`own_gap.rs`): a key listed in the print slot (first `;`-list) of `different_settings_to_system` is the user's and stays; an untouched one is FORCED to 0.75 mm × max(`nozzle_diameter`)/0.4 (evidence in the module; the owner's U1 plate lists neither key, its 0.75 is the preset's, so forcing is a no-op there), written into the probe copies and the output 3MF (`apply_own_gap`), added to the probe cache key only when it differs from the project's value, shown in the report as `own_support_gap.source` (`user|forced|kept`) and one progress line; `--keep-own-gap` keeps the project's. `support_object_xy_distance` is never forced (no evidence it matters). FOREIGN (support/base vs a neighbour's body) is packer-only: `--foreign-gaps base:band,...` (bare number = band, base 0), default = the floor alone since 2026-11-04 (the upward ladder `0:0.5,0.25:0.75,0.5:1.0,0.75:1.5` is opt-in: its upper rungs never won on the owner's plates, always 1-4 copies short, and cost three extra packs, ~60 s at the server job's two cores); `--foreign-gap-floor` (default 0:0.5, what control full-plate slices passed with zero contacts): a rung below it is refused, a lowered floor is a progress warning and `warnings` in the report. One pack per rung on the shared prints; max count wins, ties the larger band then base gap; the report has `gap_variants` (count, wall_s) and `chosen_gaps`, the chosen pair lives in `PackPlan::foreign_gaps` (state v2, missing = defaults; repacks and `PackPlan::build` revalidation use it). The final G-code check stays contact-only; `verification.min_support_body_gap_mm` (support above layer 1 to a foreign body, pairs within 3 mm) is a statistic to read against the band gap.

## Scheduler (`src/scheduler/`, `src/bin/daily_scheduler/`)

- Source must be single-plate (`plate_count_3mf` guard); build-item order is assumed to be one dense plate.
- xmltree drops namespace prefixes; `emit_core_xml` restores `p:UUID`/`p:path`/`xml:lang` by string replacement. `assemble/` avoids this by quick-xml round-trip, so keep new 3MF edits there.
- Multi-plate 3MF (`build_schedule_plates_3mf`), both locked by `tests/scheduler_plate_grid.rs`: plate grid is `cols = ceil(sqrt(n))` (not round), row-major, slot offset `bed_size * 1.2`; `wipe_tower_x/y` entries are used verbatim per plate, so every plate gets the SAME entry as the source (shifting it puts the tower off-bed, omitting it auto-places it onto objects).
- Benchmark `adaptive` (default) slices few sizes and interpolates (`origin: "interpolated"`); `--reuse-benchmarks` re-reads a prior `--output-report`.

## AMS calibration (`src/ams_calibration.rs`, `src/bin/ams_calibration.rs`)

- Generates two cube projects from the user's own 3MF (settings byte-for-byte, `Application` metadata copied: the slicers only load `project_settings.config` from a 3MF they recognise).
- A per-layer `ToolChange` applies to the layer whose `print_z == top_z` (that layer is already in the new filament), so entries carry the first layer of each band; an entry at the first layer's own z recolours it without a change (Bambu reported one change short). The binary errors when `changes_sliced != changes_expected`.

## Webapp jobs and the printer catalog (`webapp/`, `src/bin/source_project.rs`, `src/bin/printer_catalog/`)

- Probe cache on the server (`ProbeCacheService`, `ProbeCacheEntries`, V7 `probe_cache_entries`, `deploy/README.md`): the runner is untrusted and gets no shared mount, so the worker owns the cache. Before a PACK job it copies the owner's entries of the model (group = SHA-256 of `input.3mf`/`.stl`) into the job's `cache/` (tmpfs via `docker exec`), runs the packer with `--cache-dir cache` (the packer still checks its exact key), then exports `cache/` from the frozen volume, validates (name whitelist, size, JSON shape, probe's inner key = file name) and stores `probe-cache/<owner>/<group>/<id>/<name>`. Scope is per owner (guests too); LRU per model/owner + TTL through `object_gc`. Cache failures never fail a job; finish-state jobs skip it. No packer flag is needed.
- Job inputs are named `input.3mf` / `input.stl` in the job directory.
- Server sessions slide (`SESSION_SECONDS` = 7 d since last use, renewed at most daily with a fresh cookie): a hard 7-day expiry gave a guest 401 mid-work, and the next page load silently made a new guest without their jobs. Errors written outside controllers go through `writeError` (UTF-8): the servlet default ISO-8859-1 turned Russian messages into «????».
- A pack job is a URL, `/pack/<id>` (on start, from «Мои задачи», by a shared link with `#access=<token>`): the page rebuilds from the job status (`profile` = the `/profiles` DTO or the custom one, `params` = the submitted settings, `originalName`) and the input download (`GET /api/jobs/{id}/input`, server `POST /api/v2/jobs/{id}/input/download`); the form is read-only there, «Упаковать заново» returns to a draft. The bed projection is rasterized in the parse worker (`scene/projection.ts`): Chrome filled a canvas path of every mesh triangle for ~100 s on the main thread. Only a PACK from an uploaded `.stl` is an STL job; a schedule from that pack gets `packed.3mf` (its name becomes `.3mf`, worker writes `input.3mf`).
- STL jobs run `source_project && exec packer` as one shell (`ShellChain`, every arg single-quoted): one process, so in docker mode one container (its tmpfs `/work` lives until it stops), and cancel/timeout/exit code stay the packer's. `source_project` gets the profile's `--edge-margin` and rejects a model larger than the area minus margin or taller than `printable_height`.
- Slicer choice for STL jobs (`SlicerChoice`): the user prints with one of the profile's `slicers` (`{kind: gui_flavour}`, default `slicer_kind`: BambuStudio for Bambu printers, Orca otherwise; Snapmaker's Orca entry targets `snapmaker-orca-2.4`). The choice is written into the job's profile snapshot (`slicer_kind`, runner `slicer_path`, `gui_flavour`), so the runner image, `LocalSlicer` and the check child follow it; `source_project --gui-flavour` re-stamps the export's `Application` for that GUI (`project_application`: Snapmaker `Snapmaker_Orca-2.4.0` keeping Orca's tag, Bambu its own string) and the packer gets `--slicer` (explicit target flavour). `printer_catalog slicers --orca --bambu` lists another kind only when its preset tree has the machine with the same bed and start G-code as the qualified Orca preset (2026-11-03: every Bambu printer but the A2L gets Orca; no third-party printer matched Bambu Studio's tree). 3MF jobs never take a choice. Orca exports write `BambuStudio-<compat>` into `Application` plus an `OrcaSlicer` tag: read as `OrcaSlicer-<v>` (`flavour::project_generator`), not BambuStudio.
- `CustomProfile` (custom bed): `printer_name` equals the project's `printer_model` (the packer's `validate_source_printer` guard; STL → `Custom Printer`). For a 3MF the bed is always the project's own (area/origin/exclusions/height; the slicer slices by it); only the margin is user-editable, and a recognised printer cannot use a custom bed.
- Catalog profiles carry the runner image slicer paths (`/opt/slicers/<kind>/AppRun`); local mode (local services and the server's `runnerMode=local` worker) rewrites them via `LocalSlicer`.
- U1 slices in vanilla OrcaSlicer on the server on purpose (checked 2026-11-02): its first-layer goat patch (46.8x42.2 mm) matches the user's Snapmaker Orca 2.4.0 GUI (46.5x42.4), while the Snapmaker Orca 2.4.1 Linux CLI prints 50.7x45.4 mm and packs 39 instead of ~48. The 2.4.0 CLI segfaults after loading the plate (macOS and Linux); every Snapmaker Orca CLI also refuses its own 2.4 3MFs (exit 232, 'File Version 2.4.0.0 not supported by current cli version 01.10.01.50') without `--allow-newer-file`.
- Catalog profiles are generated by `printer_catalog` (extract/qualify/relabel/annotate/slicers), never hand-edited; hand-made profiles have no `source` block (or `source.manual`). A start G-code that purges in a firmware macro (`PRINT_START`, `START_PRINT`, …) with no detected purge lines gets `edge_margin_mm` ≥ 5 (`annotate`, also run in `qualify`).

## Packing safety boundary (2026-11-02)

- Every plate is checked by `PackPlan::validate` before a 3MF is written (also finish-state and time-window prefixes): the exact vector check of the core against the plan's kinds and zones.
- A checked layout is safe against the supplied geometric envelope (probe union plus δ) within numerical tolerances, NOT proof of every later tree-support realization. Runs of one goat observe a family, not its worst case; the δ margins are start values until calibration. `final_sliced: false` is explicitly unverified by slicing (the default).
- Verified plates require complete labelled-object coverage, no support/body contacts, no material outside the bed (extrusion half-width included) and what the GUI-equivalent checks accept. Slicing stays optional (`--verify`, the webapp's check job).
- Clean room: the support behaviour is reproduced from behaviour descriptions in our own code, never line by line from AGPL slicer sources (`docs/superpowers/specs/2026-11-02-slicer-free-packer-design.md` §1).
- See `docs/packing-safety.md` for tradeoffs, tests and the distinction between embedding a slicer and freezing the supports/toolpaths.
