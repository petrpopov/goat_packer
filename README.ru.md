# goat_packer

*[English version](README.md)*

Упаковывает модель в 3MF-проект слайсера, сохраняя исходные настройки печати без изменений.

На вход — 3MF с одним объектом; на выход — новый 3MF с максимумом копий на столе и тем же профилем,
филаментами и покраской. Раскладка идёт по реальному силуэту плоского дна модели (внешний контур и
отверстия), а не по габаритному прямоугольнику. Запретные зоны стола, линии очистки и башня
подкачки резервируются автоматически.

Второй инструмент планирует сутки печати на нескольких принтерах.

## Сборка

```bash
cargo build --release
cargo test --release --all
```

Тесты самостоятельны: STL/контуры и небольшие синтетические 3MF находятся в `tests/fixtures/`.
Не нужны соседние каталоги, симлинки, сеть или установленный слайсер. С закешированными
зависимостями: `cargo test --offline --release --all`.

Поиск нормализует исходный поворот/сдвиг в XY и использует детерминированные карты запрещённых
смещений, включая смешанные ориентации. Число потоков и seed не меняют результат. Это всё ещё
эвристика с точностью `--resolution`, а не доказательство глобального максимума. Для опор,
зависящих от ориентации при слайсинге, блокировка поворота сохраняется.
[Алгоритм, ограничения и воспроизводимый бенчмарк](docs/packing-search.md).
Ядро упаковки полностью локальное; существующий конвейер цветного 3MF по-прежнему вызывает
локальный слайсер из профиля принтера для пробного и финального слайсинга.

## Упаковка

```bash
./target/release/colored_3mf_packer --source in.3mf --profile profiles/p1s.json --output out.3mf
```

| Флаг | По умолчанию | Значение |
| --- | --- | --- |
| `--source` | — | исходный 3MF ровно с одним объектом |
| `--profile` | — | JSON профиля принтера (`profiles/`) |
| `--output` | — | куда записать упакованный 3MF |
| `--work-dir` | `<output>.work` | временный каталог для запусков слайсера |
| `--clearance` | `0.7` | зазор между объектами, мм |
| `--resolution` | `0.25` | размер ячейки растра, мм |
| `--angle-step` | `2.0` | шаг поворота, градусы |
| `--attempts` | `16000` | усилие детерминированного поиска; завершение после исчерпания конечного набора стратегий |
| `--candidates` | `2400` | совместимость со старым CLI; свободные позиции теперь проверяются исчерпывающе |
| `--stall` | `0` | совместимость; остановки, зависящей от порядка завершения потоков, больше нет |
| `--seed` | `20270831` | поле совместимости/отчёта; раскладка больше не зависит от случайности |
| `--support-overlap-mm` | без ограничения | насколько могут перекрываться напечатанные поддержки (патч за пределами тела) разных объектов, мм; `0` = могут касаться, но не перекрываться. Тела по-прежнему держат `--clearance` от всего чужого; без найденных поддержек ни на что не влияет |
| `--nozzle-clean` | выкл. | внедрить периодическую чистку сопла в Layer Change G-code: `global,every=10` (весь принт) или `from-z=6.6,every=1` (только с заданной высоты) |
| `--time-window-hours` | выкл. | оставить столько объектов, сколько успеет за N часов (скорректированное время, см. ниже) |
| `--ams-correction` | выкл. | поправить оценку слайсера на реальную длительность смены филамента из профиля (`filament_change_seconds`); на тулченджерах ничего не делает |
| `--change-seconds` | из профиля | реальная длительность одной смены, с (0–600); включает `--ams-correction` |
| `--time-margin-pct` | `10` | запас к скорректированному времени, % (0–50) |
| `--prep-min` | `0` | фиксированная подготовка на стол (смена листа, загрузка), минуты |
| `--no-centre` | выкл. | при окне времени: оставить раскладку от угла и исходное положение башни вместо сбора объектов и башни вокруг центра стола |

Рядом пишется `<output>.verification.json` с количеством объектов и границами башни, плюс
`supports_detected`, `support_overlap_mm`, итог проверки поддержек (`support_rule`,
`support_patch_learned`, `support_collisions`), `tower_relocated_to` при переносе башни и блок
`time` (замеры, выбранное число объектов, скорректированные секунды; с окном также `heat_zone`).

### Поддержки и башня

Если найдены поддержки, поддержки соседа могут заходить под силуэт объекта, но не на то, что он
печатает на столе (тело первого слоя); силуэты держат `--clearance` друг от друга, поддержки могут
заходить в зону башни (тела — нет). После финальной нарезки пакер проверяет G-code по всем слоям:
если поддержка касается чужого тела, он расширяет зарезервированное пятно поддержек до реально
напечатанного и перепаковывает, затем откатывается к строгому правилу (поддержки не заходят под
чужие силуэты). Без окна времени башня ставится туда, где помещается больше объектов: исходное
место или один из четырёх углов стола.

### Окно времени

Скорректированное время = `(оценка слайсера + смены × (реальная смена − смена по настройкам
слайсера) + подготовка) × (1 + запас)`. С `--time-window-hours` пакер, как обычно, пакует полный
стол и слайсит его, целится в окно по прямой через пробный слайс (1 объект) и полный стол,
слайсит этот префикс и уменьшает его (по прямой через замеренный стол окна и полный стол), пока
не уложится; не больше 4 дополнительных слайсов. Остаются объекты, ближайшие к центру стола
(самая маленькая зона нагрева профиля, A2L), туда же переносится башня (`wipe_tower_x/y`);
`--no-centre` отключает и то и другое. Ошибка, если не укладывается даже один объект, если
слайсер проигнорировал перенос башни или если башня попала бы в запретную зону принтера.

Профили с `blank_start_gcode_for_cli` (Snapmaker U1) слайсятся с пустым стартовым G-code, поэтому
их оценки и время окна не включают стартовую последовательность (парковка, нагрев, очистка);
закладывайте её в `--prep-min`.

Независимая точная геометрическая проверка результата: `./target/release/verify_outputs <stl>
<placements.json> <packed.3mf>` (минимальные зазоры, отступ от края стола, зазор до линий
очистки, запретные зоны, трансформы, CRC ZIP). Она меряет зазоры между силуэтами мешей, но не
`--support-overlap-mm` (напечатанные поддержки): перекрытие поддержек проверяет только
`validate_result` самого пакера.

## Периодическая чистка сопла

`--nozzle-clean from-z=6.6` внедряет в Layer Change G-code готового 3MF макрос протирки сопла:
каждый слой с заданной высоты (`from-z=H[,every=N]`) или каждые N слоёв весь принт
(`global[,every=N]`; `every` по умолчанию 10 для `global` и 1 для `from-z`). Сами движения
чистки берутся из профиля принтера (`nozzle_clean_gcode`): на P1/X1 — сырые G1-перемещения к
заднему лотку (макросов G150.x там нет), на A2/P2/H2 — фирменные `G150.3` + `G150.1`. Профиль
без этого поля (Snapmaker) завершается явной ошибкой. Полезно там, где белый печатается поверх
красного: у Goat 3 это зона z 6.6–8.6 мм, `from-z=6.6` чистит только её.

Для проектов, которые не собирал пакер:

```bash
./target/release/nozzle_clean_inject --source in.3mf --output out.3mf \
  --profile profiles/p1s.json --nozzle-clean from-z=6.6
```

Версии для ручной вставки в интерфейс Bambu Studio / Orca лежат в `gcode/`.

## Планирование

```bash
./target/release/daily_scheduler \
  --printer "profile=profiles/p1s.json,source=packed.3mf" \
  --output-schedule schedule.csv
```

| Флаг | По умолчанию | Значение |
| --- | --- | --- |
| `--printer` | — | повторяемый; обязательны `profile=` и `source=`, опционально `name=`, `prep-min=`, `prep-sweep=a:b:c`, `plates-3mf=<path>`, `change-s=<с>` (реальная длительность смены филамента для этого принтера, 0–600; включает для него коррекцию AMS) |
| `--output-schedule` | — | обязателен; путь для CSV с итоговым расписанием заданий по принтерам |
| `--output-report` | выкл. | опциональный путь для полного JSON-дампа (бенчмарки/чувствительность/расписание) |
| `--turnaround-min` | `10` | простой между заданиями |
| `--reuse-benchmarks` | выкл. | взять прежние замеры из `--output-report` вместо повторного слайса |
| `--ams-correction` | выкл. | добавить к каждому замеру `смены × (реальная − заложенная в слайсер смена)` по `filament_change_seconds` профиля (или `change-s=`); прежние замеры пересчитываются, но в старых отчётах числа смен нет (будет предупреждение; пересоберите замеры) |

Слайсит каждый размер партии во временном каталоге (который потом сам подчищает), чтобы измерить
реальное время печати, и оптимизирует цикл 10:00→10:00: дневные задания плюс одно ночное.

Если у `--printer` задать `plates-3mf=<path>`, дополнительно соберётся итоговое расписание этого
принтера в один multi-plate 3MF: одна `<plate>` на каждый уникальный размер партии в расписании,
каждая — обрезка `source` (убираются объекты с одного края уже готовой плотной раскладки, без
перепаковки с нуля), как и при внутреннем побатчевом бенчмаркинге.

## Калибровка AMS

Измеряет реальную длительность одной смены филамента на вашем принтере — для `--change-seconds` /
`change-s=`.

```bash
./target/release/ams_calibration --template my_project.3mf --profile profiles/bambu_a2l.json \
  --variant normal --out-dir calib/
```

| Флаг | По умолчанию | Значение |
| --- | --- | --- |
| `--template` | — | любой проект 3MF для этого принтера минимум с двумя филаментами; тест наследует его принтер, процесс, филаменты и тип AMS |
| `--profile` | — | JSON профиля принтера (`profiles/`) |
| `--variant` | — | `normal` (10 смен, примерно ±12 с) или `perfectionist` (30 смен, примерно ±4 с) |
| `--out-dir` | — | куда записать результат |

Пишет `calib_A.3mf` (кубик 20 × 20 мм филаментом 1, без смен), `calib_B.3mf` (тот же кубик ровно
с этим числом смен), `instructions.md` (инструкция для оператора) и `calibration.json`
(`variant`, `changes_expected`, `changes_sliced`, `estimate_a_s`, `estimate_b_s`,
`slicer_change_s`); в `slicing/` остаются запуски слайсера. Оба проекта слайсятся локально, чтобы
проверить число смен и что башня не задевает кубик. Напечатайте A и B, запишите время старта и
окончания, тогда `extra = ((факт_B − оценка_B) − (факт_A − оценка_A)) / смены`, а реальная смена
= `extra + slicer_change_s`.
